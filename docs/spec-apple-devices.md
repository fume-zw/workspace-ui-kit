## 1. なぜカレンダーだけでは足りないか

カレンダー（Google も Apple も）が得意なのは **時刻の枠** である。このアプリが既に持っているものは、枠だけでは表せない。

| このアプリにあるもの | カレンダーでの扱い | 結果 |
| --- | --- | --- |
| イベント・勤務の時間ブロック | 予定として自然 | 連携向き（ICS を足したあと） |
| 休みなどの終日マーカー | 終日予定で足りる | 連携向き |
| 期限だけあるタスク（時刻なし） | 終日にするか、リマインダーに逃がすかで毎回迷う | ここで崩れる |
| 未着手 / 進行中 / 至急 / 保留 / 完了 | カレンダーに状態がない | 進捗が置けない |
| プロジェクト・未割当 | カレンダーに軸がない | 分けられない。音声でも分けない |
| サブタスク | 載らない | — |
| 定期タスク（各回を独立にずらす） | カレンダーの繰り返しと意味が違う | 1回だけ変更が壊れる |
| Windows と iPhone と Watch | Google は Windows に強い。Apple リマインダーは Windows に弱い。Watch は Apple 側に寄る | 正本が分裂する |

今あるアプリは、すでに正本の形をしている。ゼロから作り直さず、**音声入口**と（必要になったら）**カレンダーへの投影**を足す。

## 2. 目指す役割分担

```
 Apple Watch  音声「追加」── POST /api/inbox ──┐
  （開始時刻あり→予定、なし→タスク）                 │
  （予定確認は、ICS を使い始めたら純正カレンダー）      │
                                                       ▼
                                              自作アプリ（正本・Supabase）
                                                Windows `/`     … 確認・編集・追加・プロジェクト割当
                                                iPhone `/mobile` … 確認・編集・追加・プロジェクト割当
                                                       │
                              検討後に足す ICS 購読     │
                       Google カレンダー / Apple カレンダー
                       Apple Watch は Apple をミラー
```

| 置くもの | 置き場 | 置かないもの |
| --- | --- | --- |
| タスクの正本 | 自作アプリ | Google ToDo / Apple リマインダー |
| 予定の正本 | 自作アプリ | カレンダー上で作った予定 |
| 音声で入ったタスク | 未割当。期限は発話にあれば付ける | 音声でのプロジェクト判定 |
| 音声で入った会議 | 時刻つきイベント（終了省略時は1時間） | 音声での勤務・終日予定 |
| 予定の見え方 | 使う段階で ICS を Google と Apple が購読 | 今すぐの必須セットアップ |

原則: **追加・編集は自作アプリ。** カレンダー側で足した予定はアプリに戻さない。

## 3. 端末ごとの要件

### 3.1 Windows PC（現行 `/`）

今の 4 ペインが本拠。Windows 用アプリは作らない。

| ID | 要件 | 現状 |
| --- | --- | --- |
| P-1 | 予定の確認・編集、タスク追加・編集・完了、未割当からプロジェクトへ割当、勤務・定期ルール | **実装済み**（音声inboxの受け皿になる） |
| P-2 | カレンダー購読 URL の発行（ICS を使い始めるとき） | 未 |

### 3.2 iPhone（`/mobile`）

音声で入った未割当を、外出先でもプロジェクトと期限を直せるようにする。Windows と同じ深さ（勤務一括・定期ルール）は求めない。

| ID | 要件 | 優先 | 現状 |
| --- | --- | --- | --- |
| M-1 | 起動時の主画面は **選んだ日の予定** | P0 | 未（初期はタスク追加） |
| M-2 | 選択日の統合アジェンダ | P0 | 実装済み |
| M-3 | タスク追加 | P0 | 実装済み |
| M-4 | イベント追加 | P0 | 実装済み |
| M-5 | イベントの編集・削除（タイトル・日時） | P0 | 未 |
| M-6 | タスクの完了、期限の変更、**プロジェクト割当**（未割当 → システム / 生化学免疫 等） | P0 | 未 |
| M-7 | カレンダー購読の設定（ICS を使い始めるとき。手順だけ先に書いておく） | P1 | 未 |
| M-8 | 勤務の一括追加・定期ルール・サブタスクは PC へ誘導 | P0 | 現行で可 |
| M-9 | ホーム画面に追加 | P1 | 未 |

### 3.3 Apple Watch

専用 Watch アプリは作らない。

| ID | 要件 | 優先 | 実現手段 |
| --- | --- | --- | --- |
| W-3 | 音声でタスクまたは時刻つき予定を追加する | **P0（先にやる）** | Siri ショートカット → `POST /api/inbox` |
| W-1 | 今日のイベント・勤務をカレンダーで確認する | P1（ICS を使い始めてから） | Apple 純正カレンダー |
| W-2 | 期限つき未完了タスクを期限日の予定として見る | P1 | 同じ ICS |
| W-4 | 開始前・期限朝の通知 | P1 | ICS の `VALARM` |
| W-5 | 手首で完了 / 文字盤の残数 / 勤務の音声追加 | — | v2 |

PC のスケジュール機能は **すでに時刻を持てる**（イベント・時間ブロック型の勤務は `startsAt` / `endsAt`）。タスクの期限だけは日付のみ（何時まで、は持たない）。音声はこれに合わせ、**開始時刻があれば予定、なければタスク** に振り分ける。

音声追加（W-3）の操作:

1. iPhone にショートカット「追加」を1つ置く（初回だけ。名前は変更可）。
2. Watch で「Hey Siri、追加」。
3. 一文を話す。
4. サーバーが **予定かタスクか** を分けて保存する。タスクならプロジェクトは見ない（常に未割当）。
5. Watch に「追加しました」と返す（「14時からの会議を入れました」でも可）。

例:

| 発話 | 入るもの |
| --- | --- |
| `試薬発注` | 未割当タスク・期限なし |
| `明日まで週報` | 未割当タスク・期限は明日 |
| `8月25日の14時から会議` | **イベント** 8/25 14:00–15:00（終了を言わなければ1時間） |
| `明日10時から11時まで週報会議` | **イベント** 明日 10:00–11:00 |
| `今日15時から会議` | **イベント** 今日 15:00–16:00 |

制約:

- iPhone が近く、ネットに出ていること。
- Siri がショートカット名を聞き取ること。
- プロジェクト名はタイトルに残し、割当には使わない。
- 勤務（当直・採血当番）は音声では作らない。PC のラベル一括のまま。
- 今すぐ直すのは iPhone `/mobile` か Windows。

## 4. 音声追加 API（先に実装する）

| ID | 要件 |
| --- | --- |
| I-1 | `POST /api/inbox`。JSON `{ "text": "…" }`。成功時に `{ kind: "task" \| "event", … }` を返す |
| I-2 | Cookie は使わない。inbox トークンで認証する |
| I-3 | `text` は前後空白を除き 1〜200 文字。空なら 400 |
| I-4 | **開始時刻が取れたらイベント**（`schedule_entries.kind = event`）。取れなければタスク |
| I-5 | タスクのとき: `status = not_started`、`project_id = null`。期限は §4.2。取れなくても追加は成功 |
| I-6 | イベントのとき: `allDay = false`、`event_label_id = null`（ラベルはあとから iPhone / PC）。終了時刻が無ければ **開始+1時間**（PC の新規イベント既定と同じ長さ） |
| I-7 | レート制限（目安: トークンあたり 30 件/時） |
| I-8 | `/mobile` にショートカット手順を書く |

Route Handler にする。分解ルールは単体テストする。

### 4.1 タスクか予定か

ショートカットは質問を増やさない。**一文をサーバーが分解する。** 基準は API 実行時点の **Asia/Tokyo**。

| 条件 | 作るもの | 理由 |
| --- | --- | --- |
| 開始時刻がある（`から` / `時に` / `○時` を開始として読める） | **イベント** | スケジュールは時刻つき。会議はここ |
| 開始時刻がなく、日付や「まで」だけ | **タスク** | 期限は日付のみ。プロジェクトは未割当 |
| 日付も時刻もない | **タスク** | 期限なし・未割当 |

「8月25日の14時から会議」は予定。「明日まで週報」はタスク。「15時まで週報」のように **終わる時刻だけで「から」が無い** ものはタスクとし、日付が取れたらその日を期限にする。**時刻はタスクに保存しない**（`due_date` に時刻列が無いため）。会議にしたいときは「15時から」と言う。

### 4.2 日付の取り方（タスクの期限 / イベントの日）

認識する日付:

- `今日` / `明日` / `明後日`
- `今週の月曜` 〜 `日曜`、`来週の月曜` 〜 `日曜`
- 単独の曜日 = 基準日以降で最初のその曜日（今日が該当なら今日）
- `M月D日` / `YYYY年M月D日` / `D日`（`D日` は基準日以降の今月、過ぎていれば翌月）

タスクで「まで」「までに」「期限」が付いていたら、その日付を `due_date` にし、語はタイトルから落とす。日付が複数なら最後の1つ。

「昨日」は使わない。プロジェクト名の辞書マッチはしない。

日付が無く開始時刻だけ（`14時から会議`）のとき: その時刻がまだ来ていなければ **今日**、過ぎていれば **明日**。

### 4.3 時刻の取り方（イベント）

認識する開始・終了:

- `N時` / `N時M分` / `N時半`（半 = 30分）/ `N:MM`
- `午前` / `午後` / `朝` / `夜`（夜7時 = 19:00）
- 午前午後がなく 1〜6 時のときは **午後とみなして +12h**（7〜23 はそのまま）
- `正午` = 12:00
- `A時からB時` / `A時からB時まで` / `A時からB時間`（B時間は開始からの長さ）

終了が開始以前なら、終了は翌日（夜をまたぐ会議）。開始が取れなければタスクに落とす。開始だけ取れて終了が壊れていれば開始+1時間。

タイトルは、日付・時刻・`から` / `まで` / `の` を除いた残り。空なら **`予定`**。

## 5. カレンダー連携（検討段階・おすすめどおり ICS）

まだ Google / Apple カレンダーは使っていない。**音声 inbox と iPhone 編集が先。** ICS は「Watch や外部カレンダーで予定を見たくなったとき」に足す。

使うときの方式（確定）: **同じ読み取り専用 ICS を、使いたい側が購読する。** Google Calendar API で書き込まない。購読は Google だけ、Apple だけ、両方、のいずれでもよい。両方だと予定が二重に見えることがあるので、手順に注意を書く。

| ID | 要件 |
| --- | --- |
| F-1 | `GET /api/calendar/[token].ics` が `text/calendar` を返す |
| F-2 | トークンはユーザーごと。URL 自体が鍵 |
| F-3 | `/mobile` と PC から発行・再発行・無効化 |
| F-4 | Google（URL で追加）と Apple（購読カレンダー）の手順を画面に書く |
| F-5 | 読み取り専用。カレンダー上で動かしても Supabase に戻さない |
| F-6 | 安定した `UID` |
| F-7 | **JST 固定** |

掲載ルール:

| 元データ | ICS 上の形 | 載せない条件 |
| --- | --- | --- |
| イベント | 時刻つき、または終日 | なし（過去も出す） |
| 勤務・時間ブロック | 時刻つき（夜勤の日跨ぎ可） | なし |
| 勤務・終日マーカー | 終日 | なし |
| 期限つきタスク | 期限日の終日。接頭辞 `タスク` | `done`、または期限なし |
| 定期タスク各回 | 上に同じ | 上に同じ |
| サブタスク | 出さない | — |
| 音声で入った期限なしタスク | 出さない | 期限を付けてから載る |

タイトル: イベントは `ラベル タイトル`、勤務はラベル名、タスクは `タスク タイトル`。

アラーム: 時刻つきは開始15分前。期限タスクは当日 08:00 JST。終日の休みは鳴らさない。

期間: **過去 30 日〜未来 90 日**。

## 6. データ・運用

- 正本は Supabase。
- トークンは推測困難。漏れたら再発行。
- 即時性: inbox / PC / iPhone はすぐ DB に乗る。カレンダー購読は数十分〜数時間遅れうる（使い始めてから）。
- 音声の成功確認はショートカットの返答で足りる。
- Watch 連携のために有料プランは必須にしない。

## 7. v2 に送るもの

- 音声でプロジェクトまで言い分ける、勤務を入れる、終日予定（時刻なしの会議）
- 手首で完了、文字盤に残数
- カレンダーの遅れがつらい、ショートカットの聞き取りがストレス
- ネイティブ watchOS（Apple Developer プログラムが必要）

v1 でやる「期限を言えば付ける」「何時から会議」「未割当に入れる」は v2 に送らない。

## 10. 受け入れ条件

**フェーズ 1〜2（カレンダーなしでも達成）**

1. Watch の Siri「追加」で一文を入れると、Windows / iPhone にすぐ見える。
2. 「明日まで週報」は未割当タスク（期限つき）。「8月25日の14時から会議」は 14:00–15:00 のイベント。
3. 「システム」「生化学免疫」と話してもプロジェクトには入らず、タスクなら未割当のままタイトルに残る。
4. 開始時刻が取れない・壊れている発話でも、タスクとして残す（落とさない）。
5. iPhone または Windows で、タスクのプロジェクト割当・期限変更・完了、イベントの時刻編集ができる。
6. 既存の 4 ペインと朝の LINE レポートを壊さない。

**フェーズ 3（ICS を使い始めたら）**

6. 同じ ICS を Google と Apple の片方または両方に購読できる。
7. 期限つき未完了タスクとイベント・勤務がカレンダーに出る。期限なしの音声タスクは出ない。
8. トークン再発行で古い購読と古いショートカットは止まる。
