## 0. 確定した判断

2026-08-20 の回答で、次を確定する。

| # | 質問 | 確定 |
| --- | --- | --- |
| 1 | Watch の音声はショートカットでよいか。プロジェクト（システム / 生化学免疫 等）は音声で分けるか | **ショートカットでよい。プロジェクトは音声では分けない。** すべて **未割当**。あとから iPhone または Windows ブラウザで割当・編集する |
| 2 | 音声で入れるもの | **タイトルは必須。期限は言ったときだけ付ける。** 言わなければ期限なし |
| 3 | Google / Apple カレンダー | **まだ使っていない。検討段階。** 使うときはおすすめどおり、同じ ICS を購読する（Google Calendar API 書き込みはしない）。**今すぐ購読しなくてよい** |

相談の結論（変更なし）: **タスクの正本は自作アプリ。カレンダーは「見える時計」であり、タスク管理の置き場ではない。**

## 1. なぜカレンダーだけでは足りないか

カレンダー（Google も Apple も）が得意なのは **時刻の枠** である。このアプリが既に持っているものは、枠だけでは表せない。

| このアプリにあるもの | カレンダーでの扱い | 結果 |
| --- | --- | --- |
| イベント・勤務の時間ブロック | 予定として自然 | 連携向き（ICS を足したあと） |
| 休みなどの終日マーカー | 終日予定で足りる | 連携向き |
| 期限だけあるタスク（時刻なし） | 終日にするか、リマインダーに逃がすかで毎回迷う | ここで崩れる |
| 未着手 / 進行中 / 至急 / 保留 / 完了 | カレンダーに状態がない | 進捗が置けない |
| プロジェクト・未割当 | カレンダーに軸がない | 分けられない。音声でも分けない |
| サブタスク | 載らない | — |
| 定期タスク（各回を独立にずらす） | カレンダーの繰り返しと意味が違う | 1回だけ変更が壊れる |
| Windows と iPhone と Watch | Google は Windows に強い。Apple リマインダーは Windows に弱い。Watch は Apple 側に寄る | 正本が分裂する |

今あるアプリは、すでに正本の形をしている。ゼロから作り直さず、**音声入口**と（必要になったら）**カレンダーへの投影**を足す。

## 2. 目指す役割分担

```
 Apple Watch  音声「タスク追加」── POST /api/inbox ──┐
  （予定確認は、ICS を使い始めたら純正カレンダー）      │
                                                       ▼
                                              自作アプリ（正本・Supabase）
                                                Windows `/`     … 確認・編集・追加・プロジェクト割当
                                                iPhone `/mobile` … 確認・編集・追加・プロジェクト割当
                                                       │
                              検討後に足す ICS 購読     │
                       Google カレンダー / Apple カレンダー
                       Apple Watch は Apple をミラー
```

| 置くもの | 置き場 | 置かないもの |
| --- | --- | --- |
| タスクの正本 | 自作アプリ | Google ToDo / Apple リマインダー |
| 予定の正本 | 自作アプリ | カレンダー上で作った予定 |
| 音声で入ったタスク | 未割当。期限は発話にあれば付ける | 音声でのプロジェクト判定 |
| 予定の見え方 | 使う段階で ICS を Google と Apple が購読 | 今すぐの必須セットアップ |

原則: **追加・編集は自作アプリ。** カレンダー側で足した予定はアプリに戻さない。

## 3. 端末ごとの要件

### 3.1 Windows PC（現行 `/`）

今の 4 ペインが本拠。Windows 用アプリは作らない。

| ID | 要件 | 現状 |
| --- | --- | --- |
| P-1 | 予定の確認・編集、タスク追加・編集・完了、未割当からプロジェクトへ割当、勤務・定期ルール | **実装済み**（音声inboxの受け皿になる） |
| P-2 | カレンダー購読 URL の発行（ICS を使い始めるとき） | 未 |

### 3.2 iPhone（`/mobile`）

音声で入った未割当を、外出先でもプロジェクトと期限を直せるようにする。Windows と同じ深さ（勤務一括・定期ルール）は求めない。

| ID | 要件 | 優先 | 現状 |
| --- | --- | --- | --- |
| M-1 | 起動時の主画面は **選んだ日の予定** | P0 | 未（初期はタスク追加） |
| M-2 | 選択日の統合アジェンダ | P0 | 実装済み |
| M-3 | タスク追加 | P0 | 実装済み |
| M-4 | イベント追加 | P0 | 実装済み |
| M-5 | イベントの編集・削除（タイトル・日時） | P0 | 未 |
| M-6 | タスクの完了、期限の変更、**プロジェクト割当**（未割当 → システム / 生化学免疫 等） | P0 | 未 |
| M-7 | カレンダー購読の設定（ICS を使い始めるとき。手順だけ先に書いておく） | P1 | 未 |
| M-8 | 勤務の一括追加・定期ルール・サブタスクは PC へ誘導 | P0 | 現行で可 |
| M-9 | ホーム画面に追加 | P1 | 未 |

### 3.3 Apple Watch

専用 Watch アプリは作らない。

| ID | 要件 | 優先 | 実現手段 |
| --- | --- | --- | --- |
| W-3 | 音声でタスクを追加する | **P0（先にやる）** | Siri ショートカット → `POST /api/inbox` |
| W-1 | 今日のイベント・勤務をカレンダーで確認する | P1（ICS を使い始めてから） | Apple 純正カレンダー |
| W-2 | 期限つき未完了タスクを期限日の予定として見る | P1 | 同じ ICS |
| W-4 | 開始前・期限朝の通知 | P1 | ICS の `VALARM` |
| W-5 | 手首で完了 / 文字盤の残数 / 音声で予定追加 | — | v2 |

音声追加（W-3）の操作:

1. iPhone にショートカット「タスク追加」を1つ置く（初回だけ）。
2. Watch で「Hey Siri、タスク追加」。
3. 一文を話す。例: 「試薬発注」「明日まで週報」「来週月曜までにシステム改修の件」
4. サーバーがタイトルと期限（あれば）に分ける。**プロジェクトは見ない。常に未割当。**
5. Watch に「追加しました」と返す（期限が取れたら「8月25日で追加しました」でも可）。

制約:

- iPhone が近く、ネットに出ていること。
- Siri がショートカット名を聞き取ること。
- プロジェクト名（システム、生化学免疫など）が発話に含まれても **タイトルの一部として残し、割当には使わない。**
- 今すぐ中身を見る・直すのは iPhone `/mobile` か Windows。

音声は **タスク追加だけ**。カレンダーに予定を入れる話はしない。

## 4. 音声追加 API（先に実装する）

| ID | 要件 |
| --- | --- |
| I-1 | `POST /api/inbox`。JSON `{ "text": "…" }`（発話の全文）。成功時に作ったタスク（`title`, `dueDate`, `projectId: null`）を返す |
| I-2 | Cookie は使わない。inbox トークンで認証する |
| I-3 | `text` は前後空白を除き 1〜200 文字。空なら 400 |
| I-4 | `status = not_started`、**`project_id = null`（未割当）固定** |
| I-5 | 期限は §4.1 で発話から取る。取れなければ `due_date = null`。**取れなくても追加自体は成功させる** |
| I-6 | レート制限（目安: トークンあたり 30 件/時） |
| I-7 | `/mobile` にショートカットの作り方（URL、トークン、Siri 名）を書く |

Route Handler にする。Server Action はショートカットから呼べない。

### 4.1 期限の取り方（JST）

ショートカットは質問を増やさない（Watch で二度聞きしない）。**一文をサーバーが分解する。**

基準日は API 実行時点の **Asia/Tokyo の日付**。

| 発話の例 | タイトル | 期限 |
| --- | --- | --- |
| `試薬発注` | 試薬発注 | なし |
| `明日まで週報` | 週報 | 明日 |
| `来週月曜までに試薬発注` | 試薬発注 | 来週の月曜日 |
| `8月25日 生化学免疫の提出物` | 生化学免疫の提出物 | 今年の 8/25（過ぎていれば翌年） |
| `システム改修` | システム改修 | なし（「システム」はプロジェクトにしない） |

認識する日付（これ以外は期限なし、全文がタイトル）:

- `今日` / `明日` / `明後日`
- `今週の月曜` 〜 `日曜`、`来週の月曜` 〜 `日曜`
- 単独の曜日（`月曜` 等）= 基準日以降で最初のその曜日（今日が該当なら今日）
- `M月D日` / `YYYY年M月D日` / `D日`（`D日` は基準日以降の今月、過ぎていれば翌月）

日付の前後の `まで` / `までに` / `期限` / `の` はタイトルから落とす。日付が複数あるときは **最後の1つ** を期限にする。

やらないこと:

- 時刻（「15時まで」）は期限日にしない。日付が無ければ期限なし。
- 「昨日」は期限にしない。
- プロジェクト名の辞書マッチ（システム、生化学免疫、検査 等）はしない。

分解ルールは単体テストする。

## 5. カレンダー連携（検討段階・おすすめどおり ICS）

まだ Google / Apple カレンダーは使っていない。**音声 inbox と iPhone 編集が先。** ICS は「Watch や外部カレンダーで予定を見たくなったとき」に足す。

使うときの方式（確定）: **同じ読み取り専用 ICS を、使いたい側が購読する。** Google Calendar API で書き込まない。購読は Google だけ、Apple だけ、両方、のいずれでもよい。両方だと予定が二重に見えることがあるので、手順に注意を書く。

| ID | 要件 |
| --- | --- |
| F-1 | `GET /api/calendar/[token].ics` が `text/calendar` を返す |
| F-2 | トークンはユーザーごと。URL 自体が鍵 |
| F-3 | `/mobile` と PC から発行・再発行・無効化 |
| F-4 | Google（URL で追加）と Apple（購読カレンダー）の手順を画面に書く |
| F-5 | 読み取り専用。カレンダー上で動かしても Supabase に戻さない |
| F-6 | 安定した `UID` |
| F-7 | **JST 固定** |

掲載ルール:

| 元データ | ICS 上の形 | 載せない条件 |
| --- | --- | --- |
| イベント | 時刻つき、または終日 | なし（過去も出す） |
| 勤務・時間ブロック | 時刻つき（夜勤の日跨ぎ可） | なし |
| 勤務・終日マーカー | 終日 | なし |
| 期限つきタスク | 期限日の終日。接頭辞 `タスク` | `done`、または期限なし |
| 定期タスク各回 | 上に同じ | 上に同じ |
| サブタスク | 出さない | — |
| 音声で入った期限なしタスク | 出さない | 期限を付けてから載る |

タイトル: イベントは `ラベル タイトル`、勤務はラベル名、タスクは `タスク タイトル`。

アラーム: 時刻つきは開始15分前。期限タスクは当日 08:00 JST。終日の休みは鳴らさない。

期間: **過去 30 日〜未来 90 日**。

---

## 6. データ・運用

- 正本は Supabase。
- トークンは推測困難。漏れたら再発行。
- 即時性: inbox / PC / iPhone はすぐ DB に乗る。カレンダー購読は数十分〜数時間遅れうる（使い始めてから）。
- 音声の成功確認はショートカットの返答で足りる。
- Watch 連携のために有料プランは必須にしない。

## 7. v2 に送るもの

- 音声で予定そのものを足す、プロジェクトまで言い分ける
- 手首で完了、文字盤に残数
- カレンダーの遅れがつらい、ショートカットの聞き取りがストレス
- ネイティブ watchOS（Apple Developer プログラムが必要）

v1 でやる「期限を言えば付ける」「未割当に入れる」は v2 に送らない。

## 9. 実装フェーズ

カレンダー未使用なので、**音声と iPhone 編集を先に出す。**

| # | 内容 |
| --- | --- |
| 1 | inbox API + 期限分解のテスト + `/mobile` にショートカット手順 |
| 2 | `/mobile` でタスクの完了・期限変更・**プロジェクト割当**（未割当の消化）。初期タブを予定に。イベント編集 |

## 10. 受け入れ条件

**フェーズ 1〜2（カレンダーなしでも達成）**

1. Watch の Siri「タスク追加」で一文を入れると、Windows / iPhone にすぐ未割当タスクが見える。
2. 「明日まで週報」のように期限を言えば `due_date` が付き、言わなければ期限なし。取れない言い方でもタスク自体は残る。
3. 「システム」「生化学免疫」と話してもプロジェクトには入らず、未割当のままタイトルに残る。
4. iPhone または Windows で、そのタスクをプロジェクトへ割当・期限変更・完了できる。
5. 既存の 4 ペインと朝の LINE レポートを壊さない。

**フェーズ 3（ICS を使い始めたら）**

6. 同じ ICS を Google と Apple の片方または両方に購読できる。
7. 期限つき未完了タスクとイベント・勤務がカレンダーに出る。期限なしの音声タスクは出ない。
8. トークン再発行で古い購読と古いショートカットは止まる。
