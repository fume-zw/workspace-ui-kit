## 0. 相談への結論

**タスクの正本は自作アプリにする。カレンダーは「見える時計」として残す。全部をカレンダーに載せる必要はない。**

やりたいことの核は次で、これは Google カレンダー + Apple カレンダーの組み合わせが苦手な領域である。

| 端末 | やりたいこと |
| --- | --- |
| Apple Watch | **予定の確認** と **音声でタスク追加** |
| iPhone | 予定の確認・編集、タスク追加（完了などの軽い更新含む） |
| Windows PC | 同じく確認・編集・タスク追加。深い作業の本拠 |

カレンダー連携が「タスク管理まで思ったようにできなかった」のは失敗ではなく、道具の向きが違う。自作に寄せてよい。ただし Watch の文字盤や Google / Apple のカレンダー画面まで自作する必要はない。

---

## 1. なぜカレンダーだけでは足りないか

カレンダー（Google も Apple も）が得意なのは **時刻の枠** である。このアプリが既に持っているものは、枠だけでは表せない。

| このアプリにあるもの | カレンダーでの扱い | 結果 |
| --- | --- | --- |
| イベント・勤務の時間ブロック | 予定として自然 | 連携向き |
| 休みなどの終日マーカー | 終日予定で足りる | 連携向き |
| 期限だけあるタスク（時刻なし） | 終日にするか、リマインダーに逃がすかで毎回迷う | ここで崩れる |
| 未着手 / 進行中 / 至急 / 保留 / 完了 | カレンダーに状態がない | 進捗が置けない |
| プロジェクト・未割当 | カレンダーに軸がない | 分けられない |
| サブタスク | 載らない | — |
| 定期タスク（各回を独立にずらす） | カレンダーの繰り返しと意味が違う | 1回だけ変更が壊れる |
| Windows と iPhone と Watch | Google は Windows に強い。Apple リマインダーは Windows に弱い。Watch は Apple 側に寄る | 正本が分裂する |

Google カレンダーと Apple カレンダーを同期しても、揃うのは **予定** までである。タスクの状態機械をどちらに持たせるかが決まらず、リマインダー・Google ToDo・カレンダー終日が混ざる。ここが「思ったようにできない」本体なので、**正本を自作に置く判断は妥当**。

今あるアプリは、すでにその正本の形をしている（Supabase にタスクと予定、Windows ではブラウザ、iPhone では `/mobile`）。ゼロから作り直す相談ではなく、**足りない出口（Watch の閲覧と音声入力、カレンダーへの投影）を足す相談**である。

## 2. 目指す役割分担（To-Be）

```
                    音声「タスク追加」
 Apple Watch  ─────────────────────────────────────────┐
  予定は純正カレンダーで見る                              │
                                                    POST │
                                                       ▼
 Google カレンダー  ←── ICS 購読 ──  自作アプリ（正本・Supabase）
 Apple カレンダー   ←── ICS 購読 ──    Windows `/`  … 確認・編集・追加の本拠
 Apple Watch       ←── Apple をミラー    iPhone `/mobile` … 確認・編集・追加
```

| 置くもの | 置き場 | 置かないもの |
| --- | --- | --- |
| タスクの正本（状態・期限・プロジェクト） | 自作アプリ | Google ToDo / Apple リマインダー |
| 予定の正本（イベント・勤務） | 自作アプリ | Google / Apple 上で作った予定を正にしない |
| 予定の見え方・通知 | Google カレンダー **と** Apple カレンダー（同じ ICS を購読） | 予定データを二重管理 |
| Watch の予定確認 | iPhone が購読した Apple カレンダーのミラー | 自作の Watch 画面（v1） |
| Watch の音声タスク追加 | Siri ショートカット → 本アプリの API | カレンダーに向かって話す |

原則: **予定もタスクも、追加・編集は自作アプリで行う。** カレンダー側で足した予定は v1 ではアプリに戻さない。戻し始めると、また正本が二つになる。

## 3. 端末ごとの要件

### 3.1 Windows PC（現行 `/`）

今の 4 ペインが本拠。新規の Windows アプリは作らない。ブラウザで本番 URL を開く。

| ID | 要件 | 現状 |
| --- | --- | --- |
| P-1 | 予定の確認・編集、タスク追加・編集・完了、勤務・定期ルール | 実装済み |
| P-2 | カレンダー購読 URL の発行・再発行も PC からできる | 未 |

### 3.2 iPhone（`/mobile`）

Safari（のちホーム画面追加）で、予定の確認・編集とタスク追加ができること。Windows と同じ深さまでは求めない。

| ID | 要件 | 優先 | 現状 |
| --- | --- | --- | --- |
| M-1 | 起動時の主画面は **選んだ日の予定** | P0 | 未（初期はタスク追加） |
| M-2 | 選択日の統合アジェンダ（タスク / イベント / 勤務） | P0 | 実装済み |
| M-3 | タスク追加 | P0 | 実装済み |
| M-4 | イベント追加 | P0 | 実装済み |
| M-5 | イベントの編集・削除（タイトル・日時） | P0 | 未 |
| M-6 | 未完了タスクの完了、期限の変更 | P0 | 未 |
| M-7 | カレンダー購読の設定（URL 表示、Google / Apple への追加手順、再発行） | P0 | 未 |
| M-8 | 勤務の一括追加・定期ルール・サブタスクは PC へ誘導 | P0 | 現行で可 |
| M-9 | ホーム画面に追加（PWA / クリップ） | P1 | 未 |

### 3.3 Apple Watch

v1 でやることは2つだけ。専用 Watch アプリは作らない。

| ID | 要件 | 優先 | 実現手段 |
| --- | --- | --- | --- |
| W-1 | 今日のイベント・勤務をカレンダーで確認する | P0 | Apple 純正カレンダー（ICS 購読のミラー） |
| W-2 | 期限つき未完了タスクを期限日の予定として見る | P0 | 同じ ICS |
| W-3 | 音声でタスクを追加する | P0 | **Siri ショートカット** → `POST /api/inbox`（下記） |
| W-4 | 開始前・期限朝の通知 | P1 | ICS の `VALARM` |
| W-5 | 手首で完了 / 文字盤の残数 / 音声で予定追加 | — | **v2**（ネイティブ watchOS） |

音声追加（W-3）の想定操作:

1. iPhone のショートカットに「タスク追加」を1つ置く（初回だけ）。
2. Watch で「Hey Siri、タスク追加」。
3. 音声でタイトルを話す。
4. iPhone が API を呼び、Supabase に `not_started` のタスクが1件入る（期限なし。プロジェクトは未割当）。
5. Watch に「追加しました」と返す。

これなら Apple Developer プログラムも Watch アプリも不要。制約は次のとおりで、受け入れ条件に書く。

- iPhone が近く、ネットに出ていること。
- Siri がショートカット名を聞き取ること。
- 期限やプロジェクトを音声で切り分けるのは v1 ではやらない（タイトルだけ）。必要ならあとから PC / iPhone で直す。
- カレンダーに反映されるのは購読の更新後。今すぐ見るなら iPhone `/mobile` か PC。

音声が「カレンダーに予定を入れて」になると、また正本がカレンダー側に逃げる。v1 の音声は **タスク追加だけ** に固定する。

## 4. カレンダー連携（Google と Apple の両方）

やりたかった「Google カレンダーと Apple 純正カレンダーで連携」は、**同じ読み取り専用フィードを両方に購読させる**形で残す。書き込みの正本は自作のまま。

| ID | 要件 |
| --- | --- |
| F-1 | `GET /api/calendar/[token].ics` が `text/calendar` を返す |
| F-2 | トークンはユーザーごと。カレンダーアプリは Cookie ログインできないので、URL 自体が鍵 |
| F-3 | `/mobile` と PC から発行・再発行・無効化 |
| F-4 | **Google カレンダー**（URL で追加）と **Apple カレンダー**（購読カレンダー）の両方の手順を画面に書く |
| F-5 | フィードは読み取り専用。Google / Apple 上で動かしても Supabase には戻さない |
| F-6 | 安定した `UID`。更新で予定が増殖しない |
| F-7 | タイムゾーンは **JST 固定** |

Watch は Apple カレンダーを見れば足りる。Google 側は Windows や他の画面で同じ予定を見るための出口である。iPhone に Google アカウントを入れている場合、同じ予定が二重に見えることがあるので、手順に「購読はどちらか一方でもよい。両方購読するなら表示するカレンダーを片方オフ」と書く。

掲載ルール（仮確定）:

| 元データ | ICS 上の形 | 載せない条件 |
| --- | --- | --- |
| イベント | 時刻つき、または終日 | なし（過去も出す） |
| 勤務・時間ブロック | 時刻つき（夜勤の日跨ぎ可） | なし |
| 勤務・終日マーカー | 終日 | なし |
| 期限つきタスク | 期限日の終日。接頭辞 `タスク` | `done`、または期限なし |
| 定期タスク各回 | 上に同じ | 上に同じ |
| サブタスク | 出さない | — |
| 音声で足した直後の期限なしタスク | カレンダーには出ない | 期限を付けてから載る |

タイトルの見分け（仮確定）: イベントは `ラベル タイトル`、勤務はラベル名、タスクは `タスク タイトル`。

アラーム（仮確定）: 時刻つきは開始15分前。期限タスクは当日 08:00 JST。終日の休みは鳴らさない。

期間: **過去 30 日〜未来 90 日**。

Google Calendar API で予定を「書き込む」方式は v1 では採らない。OAuth が増え、Apple 側と二重管理になりやすい。ICS 1本を両方購読する方が、今の「2つのカレンダーで見たい」に対して小さい。

## 5. 音声追加 API

カレンダー用とは別に、Watch / ショートカット専用の書き込み口を1つだけ足す。汎用 REST は公開しない。

| ID | 要件 |
| --- | --- |
| I-1 | `POST /api/inbox`。JSON `{ "title": "…" }`。成功時に作ったタスクを返す |
| I-2 | 認証はカレンダーとは別の **inbox トークン**（または同じトークンをパスだけ分ける）。Cookie は使わない |
| I-3 | `title` は前後空白を除き 1〜200 文字。空なら 400 |
| I-4 | 作成内容は `status = not_started`、`project_id = null`、`due_date = null` |
| I-5 | レート制限を置く（目安: トークンあたり 30 件/時）。誤作動の連打を止める |
| I-6 | `/mobile` にショートカットの作り方（URL、トークン、Siri 名「タスク追加」）を短く書く |

Route Handler にする。Server Action はショートカットから呼べない。

## 6. データ・運用

- 正本は Supabase。ICS も inbox も投影または入口。
- トークンは推測困難。漏れたら再発行。
- 即時性: PC / iPhone / inbox の成功はすぐ DB に乗る。Google / Apple / Watch のカレンダーは購読更新待ち（数十分〜数時間を約束しない）。
- 音声追加の確認はショートカットの成功表示で足りる。カレンダーにすぐ出なくても欠陥ではない。
- 可用性: 本番停止時はフィードも inbox も止まる。Resume / 再デプロイは別メモ。
- Watch 連携のために有料プランは必須にしない。

## 7. v2 に送るもの

次が欲しくなったらネイティブ watchOS を検討する。v1 の ICS とショートカットは残してよい。

- 音声で期限や「明日」を付けたい、予定そのものを足したい
- 手首で完了したい
- 文字盤に残数を出したい
- カレンダーの遅れが運用上つらい
- ショートカットの聞き取りがストレス

v2 は別リポジトリの SwiftUI。4 ペインは移植しない。Watch は今日の確認・音声追加・完了に限定する。Apple Developer プログラムが必要。

## 10. 受け入れ条件（v1）

1. Windows のブラウザで、今どおり予定の確認・編集とタスク追加ができる。
2. iPhone の `/mobile` で、当日予定の確認、イベントの追加・編集、タスク追加・完了ができる。
3. 同じ ICS を Google カレンダーと Apple カレンダーに購読できる。Watch のカレンダーに Apple 側の予定が見える。
4. Watch の Siri から「タスク追加」でタイトルだけ入り、PC / iPhone にすぐ見える。
5. 音声で入れた期限なしタスクはカレンダーには出ない。期限を付けたものだけ終日で出る。
6. トークン再発行で古い購読と古いショートカットは止まる。
7. 既存の 4 ペインと朝の LINE レポートを壊さない。
